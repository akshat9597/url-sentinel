# ByteForce Product and User Guide

## Product overview

ByteForce is an explainable URL-centric threat detection platform for authorized URL, HTTP, access-log, dataset, and PCAP telemetry. It combines readable signatures, behavioral correlation, response evidence, and an optional machine-learning model in one investigation interface.

ByteForce performs local analysis. It does not browse to submitted URLs, scan public websites, execute payloads, block requests, or collect browser history.

Open `http://localhost:5173`. API documentation is available at `http://localhost:8000/docs` and health status at `http://localhost:8000/api/health`.

### 2. Analyze a URL string

Open the Dashboard and enter a URL. The value is normalized and inspected without making a network request.

Safe examples:

```text
https://portal.example.test/search?q=hello
https://portal.example.test/search?q=%27%20OR%20%271%27%3D%271
https://portal.example.test/search?q=%3Cscript%3Ealert(1)%3C/script%3E
https://files.example.test/download?f=../../../../etc/passwd
https://gateway.example.test/preview?url=http://127.0.0.1/admin
https://githab.com/signin
https://accounts.example.test/profile?role=user&role=admin
```

These are artificial test strings. They are not sent to a target.

### 3. Interpret a result

Each detection provides:

- Attack type and optional subtype.
- Severity and confidence.
- Rule, ML, and behavior contributions.
- Matched evidence and normalization details.
- `ATTEMPT`, `PROBABLE_SUCCESS`, or `CONFIRMED_SUCCESS` outcome.

A blocked response such as HTTP 403 normally remains an `ATTEMPT`. A response body containing reliable evidence such as a file-read marker can produce `CONFIRMED_SUCCESS`. An unusually large successful response can produce `PROBABLE_SUCCESS`, but HTTP 200 alone is insufficient.

### 4. Investigate stored detections

Threat Explorer supports filters for:

- Attack type.
- Source IP or CIDR.
- Destination IP or CIDR.
- Host text.
- Severity.
- Outcome status.
- Minimum confidence.

Open a row to view the captured network event, original and normalized values, engine scores, evidence, and status reason. CSV and JSON buttons export the currently filtered view.

### 5. Load demo telemetry

Open Settings and choose **Load Demo Dataset**, or use:

```bash
curl -X POST "http://localhost:8000/api/dataset/demo/load?limit=1600"
```

The deterministic demo contains 10,000 generated records, ordinary traffic, all required attack labels, brute-force clusters, XXE and web-upload examples, and explicit outcome examples. It is intended for demonstration, not accuracy claims.

### 6. Analyze authorized logs

Operations accepts Nginx/Apache combined logs and JSON Lines from infrastructure the operator owns or is authorized to monitor. The job runs in the background and appears under Ingestion Jobs.

### 7. Analyze PCAP

PCAP Analyzer accepts `.pcap` and `.pcapng`. Zeek extracts HTTP records and ByteForce sends them through the same detector. If Zeek is unavailable, the interface offers safe demo results. Encrypted HTTPS generally requires proxy/application logs or controlled decryption.

## API quick reference

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | Service, database, ML, and Zeek status |
| POST | `/api/detect/url` | Analyze and store one URL event |
| GET | `/api/attacks` | Filter and paginate threat records |
| GET | `/api/attacks/{id}` | View one evidence record |
| GET | `/api/export/csv` | Export filtered detections as CSV |
| GET | `/api/export/json` | Export filtered detections as JSON |
| POST | `/api/dataset/upload` | Import CSV or JSON telemetry |
| POST | `/api/pcap/upload` | Process a PCAP through Zeek |
| POST | `/api/operations/logs/upload` | Queue access-log analysis |

Full API documentation is generated by FastAPI at `/docs`.
